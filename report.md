# Отчет по выполнению задания: Разработка диаграмм UML для ВКР

## 1. Предметная область

**Тема ВКР:** Разработка портативной платформы для автономного аудита беспроводных устройств на базе Orange Pi Zero 2W

**Описание:** Проект представляет собой создание автономного устройства на базе одноплатного компьютера Orange Pi Zero 2W с установленной ОС Kali Linux. Устройство предназначено для проведения аудита безопасности беспроводных сетей Wi-Fi. Основные функции включают:
- Сканирование доступных Wi-Fi сетей
- Выполнение атак типа deauth (деавторизация клиентов)
- Формирование отчетов о проведенном аудите
- Ведение журнала событий
- Управление питанием и состоянием устройства

**Акторы:**
- **Специалист по безопасности** – основной пользователь, выполняющий аудит
- **Руководитель ВКР** – контролирующее лицо, отслеживающее прогресс
- **Устройство (Orange Pi)** – исполнительный компонент, взаимодействующий с оборудованием

## 2. Подход к выполнению задания

### 2.1. Выбор инструментов
Для создания диаграмм использован **PlantUML** – текстовый язык разметки для построения UML-диаграмм. Выбор обоснован:
- Возможность хранения диаграмм в текстовом виде в репозитории
- Интеграция с IDE (VS Code, IntelliJ IDEA)
- Автоматическая генерация изображений при коммитах
- Удобство версионного контроля

### 2.2. Процесс создания диаграмм

#### Этап 1: Определение требований
- Изучение нотации UML для каждого типа диаграмм
- Анализ функциональности разрабатываемого устройства
- Выделение ключевых сценариев использования

#### Этап 2: Создание диаграмм в PlantUML
Для каждой диаграммы создан отдельный файл с расширением `.puml`:

1. **Диаграмма деятельности (подготовка к защите)** – `activity_preparation.puml`
   - Использованы узлы: начальный узел (⚫), действия (прямоугольники с закруглениями), решения (ромбы), разветвления и схождения (широкие полосы), финальный узел (⚫ с обводкой)
   - Отображает процесс от определения темы до защиты ВКР

2. **Диаграмма деятельности (процесс аудита)** – `activity_audit_process.puml`
   - Показывает технический сценарий работы устройства
   - Включает циклы, ветвления и различные режимы работы

3. **Диаграмма вариантов использования** – `usecase.puml`
   - Выделены 3 актора и 7 вариантов использования
   - Использованы отношения `<<extends>>` для связи устройства с основными функциями

4. **Диаграмма классов** – `classes.puml`
   - Определены 5 основных классов с атрибутами и методами
   - Показаны связи между классами (использование, направление данных)

5. **Диаграмма последовательности** – `sequence.puml`
   - Отображено взаимодействие пользователя, контроллера, сканера, исполнителя атак и генератора отчетов
   - Показана временная последовательность вызовов

6. **Диаграмма состояний** – `state.puml`
   - Описан жизненный цикл устройства: выключено → загрузка → готово → режимы работы → выключение
   - Вложенное состояние "Готово" с подсостояниями

#### Этап 3: Генерация кода из диаграммы классов
На основе диаграммы классов (`classes.puml`) вручную (или с использованием инструментов генерации) создан код на Python:
- `wifi_scanner.py` – сканирование сетей
- `attack_executor.py` – выполнение атак
- `report_generator.py` – формирование отчетов
- `device_controller.py` – управление устройством

Код соответствует атрибутам и методам, указанным в диаграмме, и включает заглушки для последующей реализации.

#### Этап 4: Создание прототипа CLI-интерфейса
Для дополнительного задания (посещаемость <50%) разработан прототип интерфейса в формате Mermaid:
- Отображена схема навигации по меню
- Приведен пример вывода в консоли
- Добавлены пояснения к элементам интерфейса

Так как продукт не предполагает графического интерфейса, прототип отражает консольное взаимодействие.

## 3. Демонстрация процесса генерации

### 3.1. Создание диаграммы в VS Code
1. Установлено расширение PlantUML
2. Создан файл `diagrams/activity_audit_process.puml`
3. Введен код диаграммы в нотации PlantUML
4. Использована комбинация `Alt+D` для предпросмотра
5. Диаграмма экспортирована в PNG (сохранена в `images/`)

### 3.2. Генерация кода
Для генерации кода из диаграммы классов использован подход:
- На основе атрибутов и методов из `.puml` созданы Python-классы
- Добавлены docstring и базовая реализация
- Код размещен в папке `src/`
